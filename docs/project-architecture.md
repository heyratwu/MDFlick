# MDFlick 项目架构

## 所有权与线程

| 模块 | 职责 | 生命周期 |
| --- | --- | --- |
| `application` | 文件路径到窗口的注册、首页复用、系统打开文件、共享资源注入 | 应用 |
| `applicationResources` | 文档加载槽位、图表执行槽位、图表缓存总预算与图片资源 | 应用 |
| `readerWindow` | 原生窗口、布局、链接交互、展示配置与资源服务的装配 | 窗口 |
| `documentSession` | 加载版本、取消、原文与预处理快照的统一发布 | 窗口内文档 |
| `preparedReaderDocument` | 转换后的 Markdown、预解析文档、对齐区间、Mermaid 判定 | 文档版本；从 worker 独占移交 UI |
| `diagramService` | 图表准入、去重、结果状态、缓存预算、关闭后拒绝结果发布 | 文档版本 |
| `diagramRenderer` | 文档任务队列、取消和排队期限 | 图表服务 |
| `diagramPool` / `diagramWebRuntime` | 两个应用级 worker、按需 WebView、PNG 解码、空闲回收 | 应用 / 最后一次任务后 30 秒 |
| `readerImageFrame` / `imageScheduler` | 帧提交后收集图片可见性、有界优先队列、取消离屏任务 | 构建帧 / 文档版本 |
| `imageStore` | 跨 Markdown 区域共享图片、取消、文档预算 | 文档版本 |
| `imageResources` | 全应用图片加载并发与预算统计 | 应用 |

应用共享资源由 `application` 创建并注入各窗口，不通过包级变量装配图片缓存。全应用最多同时执行两个原生文档读取/预处理任务；排队时不读取文件，取消等待不会释放其他任务的槽位。图表只在进入视口附近（上下预取 200 点）后提交，普通文档和远处图表不会创建 WebView。每文档最多同时保留 128 个源码/主题 key，文档 worker 串行送入容量为 16 的应用队列；15 秒期限覆盖文档排队、应用排队和执行。应用最多两个 worker，各独占一个按需创建的 WebView，空闲 30 秒后销毁；普通重载可复用健康运行时。WebView 仍附着创建它的原生窗口，只通过 Page 执行其他文档的任务，不跨窗口移动视图。所属窗口关闭后，后续任务重建；如果关闭打断了另一个文档的任务，在该请求的窗口重试一次。最后一个窗口关闭时取消整个池，不创建额外隐藏窗口。

图表缓存受每文档 64 MiB、应用合计 128 MiB 估算预算约束，关闭/重载时归还；WebView 自身和解码中的临时内存不计入缓存预算。任务取消或超时后，worker 销毁运行时再接下一项，避免继续复用仍在执行旧 JavaScript 的页面；WebKit 进程退出由系统管理，这仍不是进程 CPU 或内存的硬限制。

窗口、会话和图表服务的可变状态均由 UI 线程拥有。后台任务只处理捕获的输入和 `context.Context`；文档结果通过 `Window.Update` 发布，图表结果通过服务注入的 `publish` 调度器发布。重新载入先取消旧会话、关闭旧服务，再装配新版本的资源。窗口关闭统一经过 `readerWindow.close`。

图表结果回调绑定所属服务，不查找“当前窗口的缓存”。旧服务一旦关闭，即使已有发布回调在 UI 队列中，也不能恢复旧缓存。缓存满时先回收本服务的离屏结果；可见项仍无法容纳时保留源码并设置重试间隔。准入在帧提交后根据当前视口进行，避免 UI 重建时循环提交。

## 原生图片包边界

文档中的所有 SVG 统一交给浏览器渲染，不按 SVG 特性分流。`internal/svg` 仅内嵌受信任的栅格化脚本；已删除原生文字转路径、Core Text 字形桥接和 CSS 变量改写。字体、布局、CSS 变量与滤镜均采用浏览器 SVG image 模式的规则。

`svgImageRenderer` 显式注入图片加载器，后台任务复用 Mermaid 的应用级双 worker / WebView 池、队列、取消销毁与 30 秒空闲回收机制。SVG 输入以 base64 data URL 传给 `Image`，不插入页面 DOM；浏览器的 SVG image 模式禁止脚本和外部资源，保留 HTML/CSS、内嵌 data 图片和透明背景。画布按最多 2 倍分辨率输出，最大边 8192、总像素最多 1600 万；原始尺寸本身超过上限时拒绝。渲染队列与执行共享 15 秒期限，结果在 RGBA 解码前预留像素和压缩 PNG 缓存预算，显示仍使用 SVG 原有逻辑尺寸。渲染失败或未配置浏览器适配器时报告图片失败，不回退到另一套解析器。浏览器带来启动及内存开销，结果在图片缓存内复用；生成位图在大幅放大时不具备无限矢量精度。应用内置 UI 图标继续由框架管理。

`internal/imagecache.Store[T]` 负责地址归一化、并发去重、文档与应用预算、离屏回收、取消和失败重试；仅依赖标准库。构造时注入 `Loader[T]`，加载器在分配保留资源前调用 `reserve`，失败或取消时由缓存归还预留预算。地址准入策略通过 `Config.AllowSource` 注入，原生应用继续使用 `document.NativePolicy().AllowsImage`。

根包的 `image_store.go` 只装配 `Store[ui.ImageSource]`、原生加载函数和诊断记录；文件/HTTP 读取、MyGo 图片解码留在 `images.go`。`reader_images.go` 保留帧提交、Handle 几何和视口调度，通过缓存方法访问状态，不再直接操作缓存锁或条目。缓存策略测试使用假加载器，不需要 UI 框架、文件或网络；解码和视口集成测试继续覆盖原生适配层。

## 原生预处理边界

原文首次解析后，HTML 转换复用语法树；仅转换结果发生变化时再解析转换后的 Markdown。最终文档的段落、标题和表格单元格 inline 在 worker 中预热，检查取消后将整份 `parser.Document` 独占移交 UI 线程。解析器仍有可变缓存，发布后 worker 不再访问，不跨窗口或 Markdown 视图共享。

MyGo 本地 `ViewDocument` API 采用该文档；`BlockStyle` 直接配置标题、对齐段落和宽表格的原始块容器。原先的表格/段落片段生成、引用定义恢复和嵌套 Markdown 视图已移除。全文选择、复制和链接路由都在同一视图内处理。具体框架补丁及重新生成 vendor 的方式见 [MyGo 本地补丁](mygo-patches.md)。

`internal/document.ProcessingLimits` 统一限制机制。原生加载从等待应用槽位开始计时，最多 15 秒；原文和转换后的解析结果均最多 20,000 块，转换后 Markdown 最多 64 MiB。HTML token 遍历及块间 inline 预热检查取消；不发布部分文档。已无派生 Markdown 片段，因此删除片段总字节限制。预处理期限与成功加载后的图片生命周期分离。

期限是协作式的：单次 parser 调用、inline 解析和系统文件读取不能被硬中断；块数在解析完成后检查。这些限制不保证峰值 RSS 或 GPU 占用。

## 两个展示适配层

`internal/document` 提供输入校验、稳定错误码、Mermaid 语法判定、标题锚点命名以及 `DisplayPolicy`。它不依赖 MyGo UI 或 WebKit。策略函数返回值，避免一个适配层修改另一个的默认设置。

| 能力 | NativePolicy | QuickLookPolicy |
| --- | --- | --- |
| 本地图片、HTTP/HTTPS 图片 | 受预算约束地加载 | 仅替代文字 |
| data 图片 | 不加载 | 不加载 |
| HTTP/HTTPS、mailto 链接 | 默认应用打开 | 不允许 |
| 相对文档链接 | 不处理 | 不允许 |
| 标题锚点 | 窗口统一路由，包括表格/对齐段落 | 生成标题 ID，同文档导航 |
| Mermaid | 隐藏 WebView 生成 PNG | 过滤后的 HTML 中生成 SVG |
| 文档脚本 | 不执行 | 不执行；CSP 仅授权内置运行时 |

原生正文、表格、对齐段落共享链接处理器。Quick Look 的 HTML 过滤与 Swift 导航委托分别执行策略；Swift 通过 C 接口查询 Go 的导航判定，避免两种语言各维护一套地址规则。重复标题的裸锚点选择第一个同名标题。

## Quick Look 渲染边界

Swift 的 `PreviewRequest` 只持有 Go 请求注册表的整数句柄，不保存 Go 指针。新请求取消旧请求；工作闭包保持句柄存活，析构时释放。Go 请求在创建时启动 15 秒期限，覆盖 Swift 排队及 Go 渲染；同一个扩展进程最多同时执行一个 Go 渲染任务。

Quick Look 先检查块和 inline。普通 Markdown 从 AST 直接输出允许的 HTML 标签和属性，链接受共享策略限制、图片只保留替代文字，不构建整篇中间 HTML 或 DOM。含原始块级/行内 HTML 的文档，以及标题含脚注引用的文档，继续经过完整 HTML → DOM → 原地过滤链路，保留浏览器跨块容器修复、危险子树移除及标题编号行为。只对单个原始标签做独立过滤不能保证相同语义，因此不采用该做法。

两条路径均先预留页头、内置脚本和结尾，再对正文有界写入。解析块最多 20,000 个，最终 HTML 最多 64 MiB；超限或取消返回错误，不发布部分结果。直接输出在块、inline 和分段转义写入中检查取消；DOM 路径在读取、过滤和输出中检查。输入仍受共享的 32 MiB / UTF-8 限制。

最多标记前 128 个 Mermaid 图表，其余保留源码。WebKit 中使用 IntersectionObserver 按可见性渲染，预取边距 200 像素；主题切换只更新可见图表，离屏图表再次进入时更新。执行保持串行，快速切换主题时丢弃旧结果；`mdflickReady` 表示初始视口批次结束，不等待全文离屏图表。

底层 Markdown 的单次解析/HTML 生成，以及系统文件读取不能被协作式取消硬中断；取消在调用返回后生效。期限不等于进程强杀或 WebKit JavaScript 的执行上限。WebKit 的载入、图表完成时间单独记录。上述上限也不代表进程峰值内存限制。

C 渲染接口借用输入，直接校验借用字节并生成自有字符串，避免原先 `C.GoBytes`、`io.ReadAll` 等中间副本。返回的 C 字符串仍由 Swift 通过 `MDPreviewFree` 释放。旧 `MDPreviewRender` 接口保留，内部创建临时请求以维持相同所有权约定。

## 图片视口调度

原生视图通过本地 `Options.ResolveImage` API 只查询 `imageStore`，不会触发框架默认图片缓存或逐地址 goroutine。每个图片容器绑定持久 Handle，帧提交后读取最终布局坐标，覆盖滚动、窗口缩放和锚点跳转；前序 build pass 的回调自动丢弃。

可见地址优先，视口上下 200 点内的地址按距离预取，同一地址的多个位置取最近距离。每帧最多收集 128 个去重地址，待执行队列随最终帧替换，文档仅在需要时启动两个加载 worker，继续受应用最多四张图片的槽位和原有缓存预算约束。图片实际派发前不创建缓存条目。每批解码完成后等待下一次帧提交重新评估布局，避免图片展开后继续派发已经离屏的占位内容。

地址离开预取区域后移除等待任务，并取消正在加载或等待应用槽位的任务。取消不缓存为永久失败，快速滚走又返回也可重新派发；已完成图片在预热预算内保留，超限回收时由视图继续保留尺寸。系统读取、图片/SVG 解码仍是协作式取消，返回后才释放临时结果与预算。关闭和重载取消整个旧调度器及图片缓存。

## 2026-11-02：可回收资源与视口队列

重载和关闭同时释放会话的原文与预解析快照。解析器仍独占移交 UI；没有引入跨窗口 AST 缓存。

Mermaid 和图片一样，在最终帧提交后根据 Handle 坐标收集视口需求。图表文档等待队列按距离重排；离屏和旧主题的等待任务取消，应用池真正开始使用运行时后则允许任务完成。取消尚未执行的任务不销毁健康 WebView。服务为每次提交分配 ticket，防止滚走再返回时旧回调覆盖新任务。应用池仍按文档到达顺序处理，未实现跨窗口抢占或全局距离排序。

图片与图表的文档缓存可以回收已完成的离屏项。帧提交后图片保留至多 16 MiB、图表至多 8 MiB 的离屏预热空间（可见项不受这两个软目标限制），并把已完成条目数尽量降到 64 以下；加载/接收结果时，还会按原有硬预算回收本缓存的离屏项。原有每文档/应用字节预算、并发数和最多 128 个驻留地址/key 保持不变，128 不再限制文档整个生命周期曾展示过的资源总数。回收不保证 LRU 顺序，也不会跨窗口夺取其他文档的缓存；多个窗口都接近应用总预算时，仍可能暂时拒绝新资源。

图片的持久局部状态仅保存原始宽高和 Handle，Mermaid 保存逻辑宽高和 Handle；它们不持有已回收的位图。占位容器保持宽高比并适应窗口宽度，避免正文收缩；图表头部和复制源码按钮也保留。回收后请求下一帧，以解除旧提交帧仍持有的位图引用。实际 GPU/WebKit/Go 堆回收由各自运行时决定，预算归还不是 RSS 已下降的证明。

网络超时、HTTP 429/5xx、资源预算不足以及图表取消/超时设置两秒重试间隔；之后再次进行视口评估时允许重试，不启动轮询定时器。图片解码错误等确定性失败仍缓存到回收或重载。正在执行的任务不会因滚动被重复打断。

主窗口超过 32 KiB 的代码块采用等宽纯文本，保留完整内容、选择和复制，跳过语法分词和逐行宽度测量；超过 4096 字节的单行不再单独测宽。未改变的代码块通过解析块 revision 复用高亮状态。主窗口继续全量构建 Markdown；块级虚拟化的兼容性边界和后续验收条件见 [性能验证](performance.md#长文虚拟化的兼容性边界)。
